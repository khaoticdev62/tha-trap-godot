## 3. Research vs recommendation
**Verified:** source publication dates, named framework versions and high-level scope as stated by the official source pages.

**Recommendation:** curriculum order, mission design, palette, district names, architecture, performance targets, rubrics, story, asset sources and product scope. These are original design choices, not official requirements.

## 4. Framework change workflow
1. Check official source and version.
2. Record release date and retrieval date.
3. Diff new and prior framework data.
4. Identify changed tactics, techniques, controls, tasks, categories and mitigations.
5. Map affected lessons, missions, hints, assessment criteria and portfolio outputs.
6. Have a subject-matter reviewer approve mapping changes.
7. Update versioned curriculum data.
8. Add regression tests.
9. Publish player-facing change notes.
10. Preserve completed historical assessment versions.

## 5. Change-impact levels
- Critical: a lesson teaches unsafe or materially incorrect behavior; disable or correct promptly.
- High: framework update materially changes a core learning objective or response practice.
- Medium: terminology, mapping or example changes; schedule next content update.
- Low: editorial or reference link update.

## 6. Source-use and IP policy
Use frameworks and public guidance as references, but write original explanations, missions, dialogue, synthetic data and scoring rubrics. Respect trademarks and attribution requirements. Do not reproduce proprietary third-party labs, screenshots, course text or datasets.
