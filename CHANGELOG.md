# Changelog

All notable changes are recorded here. Format: [Keep a Changelog](https://keepachangelog.com/); versions follow SemVer.

## [Unreleased]

### Added
- Evidence, case and timeline (milestone M5): `EvidenceLedger` (never-reused ids, only real events, idempotent re-collection, caps), `CaseFile` with facts, hypotheses and unknowns (a fact must cite evidence), severity and scope, `TimelineBuilder`, and `LabSession` as the single facade (`add_evidence`, `add_case_entry`, `set_severity`, `set_scope`, signals, `state_problems()`). Evidence cited by the case cannot be removed. `LabSession.snapshot()` and `restore()` give a JSON-safe, fully validated save of the player's work (all-or-nothing; refuses a different scenario, difficulty or seed; the 64-bit seed is stored as text). `state_hash()` now covers the case, and `reset()` clears it.
- Terminal commands for the case: `evidence add|list|remove`, `case note|severity|scope|show`, `timeline build` (commands that change the lab are flagged `mutates` in the table). `case report` and recommendations arrive with assessment (M6).
- Tests: a scripted full LAB-001 investigation through the terminal, snapshot round trips including corrupt-data refusals, and a seeded fuzz proving no command sequence can leave the lab inconsistent.
- Sandboxed lab terminal (`TerminalParser`, `TerminalTokenizer`, `TerminalCommands`, `TerminalResult`; milestone M4, decision D-006). A hand-written tokenizer with no shell features (no pipes, chains, redirects, variables, globs, paths or escapes), a closed command table (`help`, `clear`, `history`, `assets list`, `hosts show <host>`, `logs search key=value ...`), host commands refused by name with an explanation (`ls`, `curl`, `powershell`, ... over 100 names), `match`-based dispatch (never a lookup from player text), plain-word argument validation, capped line length, token count, history and output (every result including errors passes through `limit_output`), and read-only handlers. `logs search` builds a query tree directly rather than assembling query text. Evidence, case and timeline commands arrive with M5, when those services exist (no stubs).
- Security suite for the terminal (`tests/security/test_terminal_safety.gd`): host commands in several spellings, shell syntax, paths, quoted payloads treated as data, malformed lines, size limits, 3,000 seeded random inputs, wrong-argument checks, and the property that no input changes the lab state hash. The isolation scan now also forbids dynamic dispatch and reflection (`.call(`, `Callable`, `ClassDB`, `set_script`, ...) under `scripts/simulation/`.
- SIEM-style query engine (`QueryEngine`, `QueryTokenizer`, `QueryParser`, `QueryExecutor`, `QueryResult`, `ParsedQuery`; milestone M3, decision D-009): `FROM source [WHERE cond] [AFTER t] [BEFORE t] [GROUP BY f] [COUNT] [SORT f [ASC|DESC]] [LIMIT n]` with AND/OR/NOT, parentheses, `=`, `!=`, `CONTAINS`, case-insensitive matching, ISO or clock times. Hand-written; no evaluation of query text. Limits: 512 characters, 128 tokens, 8 nesting levels, LIMIT 1-500, and a work budget. Errors are written to teach (they name the fix). Results carry event ids per row so they can become evidence. AFTER is inclusive and BEFORE exclusive.
- Golden-query tests against the LAB-001 story events (unchanged at every difficulty) and a seeded fuzz suite (`tests/security/test_query_fuzz.gd`: token soup, random and hostile characters, mutations of valid queries, pathological inputs).
- Simulation kernel (`scripts/simulation/`, milestone M2): `EventRecord`, `EventStore` (ordered, hashable), `ScenarioPackage`, `ScenarioGenerator` (seeded noise and decoys; difficulty changes noise only, never the story events), and `LabSession` (`state_hash()` and `reset()` back to the exact baseline). Shipped data: `data/labs/lab_001/scenario.json` with the six canonical LAB-001 events plus baseline context, assets and identities; `ContentCatalog` validates it (unique ids, noise never reuses a story actor, noise grows with difficulty).
- `tests/security/` and a static isolation scan that fails if anything under `scripts/simulation/` uses `OS.*`, `Time.*`, unseeded random calls, file or network classes, `Expression`, `load`/`preload`, the scene tree, UI classes or services (proved by planting violations). The test runner now discovers `tests/unit` and `tests/security`.
- Note: `ContentCatalog` (data layer) references simulation schemas by design; it is the one place that knows both.
- Content validator CLI (`tools/content_validator/validate.gd`; exits 1 on any problem; runs in `run-tests.ps1` and CI), `ContentCatalog` with the LAB-001 manifest schema and `data/labs/lab_001/manifest.json`. Registry entries can carry an extra check; the lab check requires every manifest to forbid `host_shell`, `external_network` and `real_credentials` and never allow a forbidden action. Manifest paths to the scenario, rubric and events are not yet checked for existence (those files arrive in M2/M6).
- `ContentRegistry` and `ContentLoader` (`scripts/data/`): content is loaded by registered id only (never a caller path), with a per-file size cap, malformed-JSON errors that carry a line number, a required `schema_version` (newer versions refused), schema validation, and `validate_all()` that reports every bad document together. Schemas live in code for now rather than `data/schema/*.json`; revisit when more than one lab exists.
- `SchemaValidator` and `ContentResult` (`scripts/data/`): declarative validation for untrusted content (types, ranges, enums, stable ids, text safety incl. control/zero-width/bidi characters, nesting cap, error cap, safe relative content paths, duplicate-id finder). First piece of milestone M1; no content or loader yet.
- Phase 1 audit documents (`docs/audits`, `docs/architecture`, `docs/production`) and the production specs under version control in `docs/spec/` (decisions D-008 to D-013 recorded in `00`).
- Local pre-push test gate (`tools/hooks/pre-push`, `tools/install-hooks.ps1`) as a stand-in for CI.
- Credential-free export presets for Windows and Linux x86_64 (`export_presets.cfg`, no longer git-ignored; verified to load and pack resources with Godot 4.7.2; full export needs export templates, not yet tested).
- License: Apache-2.0 for code (`LICENSE`, `NOTICE`); creative content and names stay all rights reserved (`LICENSES.md`).
- Phase 1 foundation: Godot 4.7 project (GL Compatibility renderer, 1280x800 base), boot flow, EventBus, SceneFlow with an id registry, SaveService (atomic writes, verification, rotating backups, checksums, schema migrations, corruption recovery), PlayerProfile with strict sanitising, local redacting diagnostics, controller-complete input actions, and a functional title screen (Continue / New Game / Quit).
- UI foundation: palette-driven global Theme (scalable text 75-200%, high-contrast scheme, thick shape-based focus rings), persisted AccessibilitySettings (`user://settings.json`, atomic writes, corrupt files fall back to defaults), `motion_duration()` for reduced motion, and a working Settings screen reachable from the title screen (ui_cancel / B goes back).
- `DialogueBox`: speaker, typewriter reveal, branching choices. Accept finishes a line early, then advances; nothing is timed. Honours reduced motion and a new dialogue text speed setting (Slow / Normal / Fast / Instant). Lines are plain text and capped (1200 chars, 6 choices).
- `HintBar`: help text that follows keyboard/controller focus as well as the mouse; used on the Settings screen.
- Reusable `ModalDialog` (focus trapped between its buttons, starts on the safe choice, ui_cancel cancels, focus returns to the opener) used for the start-over confirmation.
- Character creator wired into New Game: name, optional pronouns, skin tone, hair and outfit colour. Choices are cosmetic, stored as stable ids and validated on load (unknown ids fall back to defaults).
- Headless unit test runner and a title-screen integration test (`tools/run-tests.ps1`), with a per-scene timeout.

### Changed
- CI runner pinned to `ubuntu-24.04`.
- EventBus signals annotated `unused_signal` (they are emitted by forwarding in AppBootstrap); a debug run now reports zero engine warnings.
- Visual review (real renders via `tools/visual/capture.tscn`) found and fixed: modal and dialogue box mis-positioned (anchors without offsets), Settings/Title not scrollable at large text, invisible slider track, unstyled text fields and dropdown popups, toggle state shown only by a tiny icon (now "On/Off" in the label), pillarboxing at 16:9 (stretch aspect is now `expand`), and screens ignoring the high-contrast page colour (`PageBackground`).
- New Game now goes through the character creator; the profile is written only when the creator finishes, so backing out never destroys an existing save.
- Pronouns are a fixed list of options rather than free text.
- Accessibility preferences moved out of `PlayerProfile` into `AccessibilitySettings` so they apply before a save is loaded.
- Pressed-button style now uses the Obsidian background: white on Signal Purple measured 4.39:1, below WCAG AA 4.5:1.
